Method, interpretation and limits

The workloads, checks and timing procedure are those of stdVBA's regex benchmark (Tools/stdRegex, branch codex/issue-141-regex-analysis), extended with more ASF versions. Every timing sample was accepted only after output checks: the expected Boolean for Test, every numbered capture and the match count for MatchAll, the complete replacement string for Replace. Cells marked "Not equivalent" failed that check and are left out of the comparisons.

The clock runs inside Basic (QueryPerformanceCounter), excluding automation calls. Each cell is calibrated to at least 30 ms per batch, up to 16,384 iterations, followed by five timed batches. The whole experiment ran twice in separate processes; the tables show medians of the resulting ten batch averages per call, not individual-call latency percentiles. Engine order rotates between workload/operation cells.

Compile + first Test builds a fresh object, so constructor caches are bypassed; ASF's compiled-pattern cache (v3.2.0 and later) belongs to each object unless shared through SharedCache, so every fresh object compiles. Other operations reuse preinitialized objects. Native processing limits are raised to 2,147,483,647. These small inputs do not test pathological backtracking.

Capture output is a confounder for MatchAll: stdRegex returns dictionaries, ASF returns collections. Building 100 result containers without any regex work took dictionary: 120.088 ms; collection: 0.854 ms in this run.
